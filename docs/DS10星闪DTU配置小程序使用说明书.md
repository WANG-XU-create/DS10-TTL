## 00 配置总览

本手册先帮你确定设备要作为主机还是从机，再按对应路径完成配置。主机需要配置全部三项，从机只需要配置硬件参数。

### 适用设备

| 型号 | 接口 |
|------|------|
| DS10-TTL | TTL 串口 |
| DS10-R485 | RS-485 接口 |
| DS10-R232 | RS-232 接口 |

### 完整配置流程

`01 进入小程序 → 02 选择主/从 → 03 连接并读取 → 04 按角色配置 → 05 保存并复查 → 06 切换 RUN`

> **关键顺序**：配置前先把硬件开关拨到 DEBUG。连接设备后先读取，修改完再保存；保存后必须重新读取。只有配置完全一致时，才能把开关拨到 RUN。

### 按设备角色阅读

| 设备角色 | 配置路径 | 需要完成的内容 |
|----------|----------|----------------|
| 主机 | 01 → 02 → 03 → 04 → 05 → 06 | 主机配置、通道管理、硬件配置，最后保存并切到 RUN。 |
| 从机 | 01 → 02 → 05 → 06 | 跳过主机配置和通道管理，只完成硬件配置。 |
| 升级 / 排查 | 查看 07 | 升级固件，或根据故障现象查找原因。 |

### 开始前确认

- 主设备和待绑定从设备均已正常上电。
- DS10 的 RUN / DEBUG 开关已拨到 DEBUG。
- 手机蓝牙与定位服务已经开启。
- 已确认设备机身上的 SN 或配置二维码。
- 已知现场串口的波特率、数据位、校验位和停止位。
- 微信已获得蓝牙、定位和相机权限。

## 01 进入小程序并选择角色

本章只做两件事：进入 DS10 配置页，并根据业务需要确定设备是主机还是从机。

> **本章目标**：成功进入小程序 · 打开 DS10 配置页 · 确认主机 / 从机路径

### 1.1 进入 DTU 配置工具小程序

可以扫描小程序码，也可以直接在微信中搜索。两种方式进入的是同一个配置工具。

| 进入方式 | 如何操作 |
|----------|----------|
| 扫码进入 | 打开微信"扫一扫"，扫描小程序码。 |
| 搜索进入 | 在微信中搜索"DTU 配置工具"，点击小程序进入。 |
| 首次使用 | 微信询问是否允许使用蓝牙、定位或相机时，请选择"允许"。 |

*（图 1-1：DTU 配置工具小程序码）*

### 1.2 允许小程序发现设备

1. **开启手机功能**：打开手机的蓝牙和定位服务（GPS）。
2. **授予微信权限**：在系统设置中允许微信使用蓝牙、定位和相机。
3. **接受小程序授权**：首次扫码或搜索时，在授权弹窗中点击"允许"或"同意"。

> **Android 注意**：部分 Android 手机关闭定位后，微信会搜不到蓝牙设备。如果一直搜索不到，请先确认手机定位（GPS）已经开启。

### 1.3 进入 DS10 配置页

打开"DTU 产品中心"后，在"星闪 DTU"分类中点击 DS10 产品卡片，即可进入 DS10 配置页。

*（图 1-2：点击 DS10 产品卡片；图 1-3：进入 DS10 配置页，先确认主模式或从模式）*

### 1.4 选择主模式或从模式

进入 DS10 配置页后，先根据设备的实际用途选择模式。主模式用来管理和绑定从机；从模式只需要设置设备自身的硬件参数。

| 对比项 | 主模式 | 从模式 |
|--------|:------:|:------:|
| 主机配置 | ✓ | — |
| 通道管理 | ✓ | — |
| 硬件配置 | ✓ | ✓ |
| 适用情况 | 设备作为主机，需要管理从机和数据通道。 | 设备作为从机，只设置串口、发射功率等硬件参数。 |

> ✓ 可配置 · — 该项不显示

**完成标准**：已进入 DS10 配置页，并明确当前设备要配置为主机还是从机。

## 02 连接目标设备

主机和从机都要完成本章。先选中正确的设备并建立蓝牙连接，再读取设备中已有的配置。

> **本章目标**：设备 SN 无误 · 状态显示"已连接" · 已读取当前配置

### 2.1 锁定并连接目标设备

页面顶部的"目标设备（TARGET）"卡片表示当前要配置哪一台设备。先通过扫码或搜索选中设备，再连接蓝牙。

| 添加方式 | 适用情况 | 操作 |
|----------|----------|------|
| 扫码添加 | 设备在手边，希望避免选错。 | 扫描设备外壳上的配置二维码。 |
| 搜索添加 | 二维码损坏或不方便扫描。 | 根据设备 SN 或 MAC 地址确认后选择。 |

*（图 2-1：搜索并核对目标设备；图 2-2：点击"未连接"建立蓝牙连接，等待状态变为蓝色"已连接"）*

> **注意状态**：看到设备名称只代表已经选中设备，还没有连接。请继续点击灰色的"未连接"，直到它变为蓝色"已连接"。

### 2.2 读取设备当前配置

1. **确认连接**：顶部状态必须为蓝色"已连接"。
2. **读取配置**：点击页面底部"读取配置"，等待设备 SN、型号、软件版本和各项设置显示出来。
3. **确认设备**：检查页面中的 SN 是否和设备机身标签一致。

> **不要跳过**：如果设备以前配置过，直接修改可能会用页面默认值覆盖原来的设置。修改任何参数前先执行读取配置。

**完成标准**：设备 SN 正确，状态显示"已连接"，页面显示的是刚从设备读取的设置。

## 03 主机配置

本章只适用于主机。如果当前设备是从机，请直接跳到第 05 章"硬件配置"。

> **主机配置顺序**：选择常规 / 专家 · 选择工作模式 · 需要时再调整高级参数

### 3.1 常规模式与专家模式

专家模式包含常规模式的全部功能，并增加规则路由和无线高级参数。

| 功能项 | 常规模式 | 专家模式 | 用途 |
|--------|:--------:|:--------:|------|
| 广播模式 | ✓ | ✓ | 把同一份数据发送给所有已启用的从机。 |
| Modbus 模式 | ✓ | ✓ | 按照 Modbus 站号把数据发给指定从机。 |
| 规则路由 | — | ✓ | 根据自定义数据内容选择接收数据的从机。 |
| 广播发送方式 | ✓ | ✓ | 选择可靠、非可靠或智能混合广播。 |
| NTP 授时 | ✓ | ✓ | 仅在非可靠广播和智能混合广播下可启用。 |
| 帧类型 | ● | ✓ | 在 GFSK 和 Polar 码之间选择。 |
| 性能档位 | ● | ✓ | 选择距离优先、均衡模式或速率优先。 |
| PHY / MCS / 导频 / 超时 | — | ✓ | 进一步调整无线距离、速度和稳定性。 |

> ✓ 可设置 · ● 使用默认值 · — 当前模式不提供

> **选择建议**：大多数用户使用常规模式即可。只有需要规则路由，或者需要手动调整无线参数时，才切换到专家模式。
>
> **谨慎调整**：PHY、MCS、导频是无线高级参数。如果没有明确的测试结果，请保持默认值。

*（图 3-1：常规 / 专家模式切换）*

#### 根据使用场景选择工作模式

| 你的场景 | 选择 | 数据行为 | 注意事项 |
|----------|------|----------|----------|
| 所有从机接收同一份数据 | 广播 | 向所有已使能从机发送。 | 选择可靠、非可靠或智能混合。 |
| 按 Modbus 站号发送给指定从机 | Modbus | 设备读取 Modbus 数据中的站号，再发送到对应通道。 | 站号范围为 1–247。 |
| 根据自定义数据内容选择从机 | 规则路由 | 按照用户设置的规则，把数据发到指定通道。 | 只在专家模式中显示。 |

**广播类型对比**

| 广播类型 | 数据长度 | 发送方式 | 授时 |
|----------|----------|----------|:----:|
| 可靠广播 | 每帧最大 1500 字节；1501–4096 字节时自动分包发送。 | 逐台发送并等待确认，适合对可靠性要求较高的数据。 | — |
| 非可靠广播 | 每帧最大 256 字节；超出的数据会被截断。 | 一次发给所有从机，不等待接收确认。 | ✓ |
| 智能混合广播 | 按识别头匹配后的发送路径，执行对应的长度规则。 | 根据已配置的数据包识别头，自动选择对应的通道路径。 | ✓ |

*（图 3-2：可靠、非可靠与混合广播对比）*

#### NTP 授时数据格式

> **启用条件**：NTP 授时只能在 **非可靠广播** 或 **智能混合广播** 下启用；可靠广播不支持启用该功能。

**1. 数据应如何排列**

授时数据由"可配置识别头 + NTP64 时间"组成。NTP64 共 8 字节：前 4 字节为 NTP 秒字段，后 4 字节为 NTP 小数字段。

以识别头 `AA 55` 为例：

| 识别头 | NTP 秒字段 · 4 字节 | NTP 小数字段 · 4 字节 |
|--------|---------------------|-----------------------|
| `AA 55` | `83 AA 7E 80` | `00 00 00 00` |

完整示例：`AA 55 83 AA 7E 80 00 00 00 00`

**2. 主机与从机如何处理**

| 顺序 | 处理过程 |
|------|----------|
| 01 | 向主机串口写入精准时间时，必须按照"识别头 + NTP 秒字段 + NTP 小数字段"的格式发送。 |
| 02 | 主机识别到匹配的数据包头后，通过 SLE 链路把授时数据发送给从机。 |
| 03 | 从机收到数据后，会自动计算时间，并从串口输出计算后的时间数据。 |

> **时间说明**：从机输出的时间已计入 SLE 链路耗时，但不包含串口传输本身消耗的时间。如果业务对端到端时间精度要求较高，还需在应用程序中单独考虑串口耗时。

*（图 3-3：Modbus ID 路由——从 Modbus 报文中读取目标 ID，再发送给匹配的从机；图 3-4：规则路由——根据输入数据内容匹配规则，再发送给指定从机）*

### 3.2 SLE 参数配置

SLE 参数由两个选项组成：
- **选项一 · 帧类型**：GFSK · 高功率、Polar 码 · 高速
- **选项二 · 性能档位**：距离优先、均衡模式、速率优先

两个选项组合后，共有 6 种预设场景。

| 帧类型 | 距离优先 | 均衡模式 | 速率优先 |
|--------|----------|----------|----------|
| **GFSK · 高功率**（覆盖和穿透优先） | 组合 1 · 远距离覆盖（距离较远或遮挡较多） | 组合 2 · 常规工业现场（兼顾覆盖、稳定和速度） | 组合 3 · 覆盖与吞吐（保留高功率，同时提高速度） |
| **Polar 码 · 高速**（纠错和传输效率优先） | 组合 4 · 远距离稳定（距离较远，并兼顾编码纠错） | 组合 5 · 高速均衡（兼顾稳定性和传输效率） | 组合 6 · 高速传输（距离较近、数据量较大） |

> **如何选择**：不确定现场适合哪一组时，先选择对应帧类型的"均衡模式"，再根据实际距离和传输速度调整。

**完成标准**：已根据现场的距离、遮挡情况和数据量，选择合适的 SLE 帧类型与性能档位。

## 04 通道管理（仅主机）

本章只适用于主机。主机提供 15 个通道，每个通道可以绑定一台从机。先把从机添加到主机通道，再根据主机的工作模式完成通道配置。

### 4.1 主机通道添加从机设备

1. **开启目标通道**：打开需要使用的通道。需要同时开启或关闭全部通道时，可使用列表顶部的"通道使能"。
2. **添加从机设备**：每个通道最多绑定一台从机。根据现场情况，从下面选择合适的添加方式。

| 现场情况 | 推荐方式 | 关键动作 |
|----------|----------|----------|
| 单台设备，SN 已知 | 手动输入 / 单扫 | 输入 SN，或点击输入框旁的扫码图标。 |
| 明确要放入某个通道 | 通道快速扫码 | 点击该通道右下角扫码图标。 |
| 需要连续添加多台设备 | 连续扫码分配 | 按照"已打开且未绑定"的通道顺序自动添加。 |
| 二维码不方便扫描 | 扫描附近设备 | 从搜索结果中选择设备，或一键添加到空闲通道。 |

*（图 4-1：指定通道绑定从机，支持扫码或手动输入 SN；图 4-2：批量绑定入口，快速扫码与扫描附近）*

> **连续扫码提示**：手机振动表示当前设备已经添加成功。约 800 ms 后可以继续扫描下一台设备。开始前，请先打开足够数量的通道。

### 4.2 不同工作模式下的通道配置

从机添加完成后，根据主机当前使用的工作模式，确认通道是否还需要继续设置。

- **01 · BROADCAST 广播模式**：无需额外配置
- **02 · MODBUS 模式**：绑定 Modbus ID
- **03 · RULE 规则路由**：仅专家模式可用

**① 广播模式**

> **无需配置**：广播模式会把数据发送给所有已启用的通道。添加从机并打开通道后，不需要再设置 Modbus ID 或规则路由。

**② Modbus 模式**

在 Modbus 模式下，需要在主机端建立"通道 ↔ Modbus ID"的绑定关系。每个通道都有自己的 ID 列表，主机使用这份列表建立 Modbus 数据与通道的对应关系。

> **核心规则**：一个通道可以绑定一个或多个 Modbus ID；同一个 Modbus ID 也可以同时绑定到不同通道，跨通道重复不算冲突。

绑定关系示例：

| 主机通道 | 绑定的 Modbus ID |
|----------|------------------|
| 通道 1 | ID 1, ID 2 |
| 通道 2 | ID 1, ID 5 |
| 通道 3 | ID 10 |

常用操作：

| 操作 | 规则 |
|------|------|
| 新增 ID | 站号范围为 1–247。多个站号之间用逗号分隔。 |
| 删除单个 ID | 点击标签右侧"×"。 |
| 清空通道 ID | 点击"清空"移除当前通道的全部站号。 |

*（图 4-3：主机通道绑定 Modbus ID，ID 1 同时绑定在通道 1 和通道 2）*

**③ 规则路由**（仅专家模式可用）

规则路由用来判断"收到的数据应发给哪台从机"，以及"从机返回的数据要不要加上来源信息"。

| 方向 | 配置项 | 规则 |
|------|--------|------|
| 发送给从机 | 匹配方式 | 可按数据开头、固定位置或是否包含某段内容来判断。 |
| 发送给从机 | 起始位置 | 从第几个字节开始检查，可设置 0–1024。 |
| 发送给从机 | 匹配数据 | 使用 HEX 格式，最多 32 字节。 |
| 从机返回数据 | 变量模板 | 可使用 `{channel}`（通道号）、`{sn}`（设备 SN）。 |
| 从机返回数据 | HEX 帧头 | 可在返回数据前加上固定内容、通道号或数据长度。 |
| 从机返回数据 | 回复预览 | 在保存前查看返回数据最终会是什么样子。 |

*（图 4-4：规则路由参数入口；图 4-5：发送规则与返回格式）*

> **模板示例**：设置 `[CH{channel},SN={sn}]` 后，如果数据来自通道 1、设备 SN 为 DS10001，返回数据前会加上 `[CH01,SN=DS10001]`。

**完成标准**：每台从机都已添加到正确通道，通道也已打开；广播模式无需额外设置，Modbus ID 或规则路由已按当前工作模式完成配置。

## 05 硬件配置（主机 / 从机通用）

主机和从机都要检查本章。从机不显示"主机配置"和"通道管理"，只需要配置本章的四项功能：串口参数、SLE 发射功率、软调试模式和 STATUS 引脚作用。

### 5.1 串口参数

串口参数必须与连接的 PLC、传感器或其他串口设备保持一致。参数不一致时，设备可能无法正常收发数据。

| 参数 | 说明 |
|------|------|
| 波特率 | 必须从下方列出的波特率中选择，并且不能超过当前 DS10 型号的上限。 |
| 数据位 | 7 / 8。 |
| 校验位 | 无 / 奇 / 偶。 |
| 停止位 | 1 / 2。 |

*（图 5-1：硬件配置页面）*

**完整支持的波特率枚举**

`1200`、`2400`、`4800`、`9600`、`14400`、`19200`、`38400`、`57600`、`115200`、`230400`、`460800`、`921600`、`1000000`、`1500000`、`2000000`、`3000000`、`4000000`

**不同型号的波特率上限**

| 设备型号 | 硬件最高波特率 | 符合上限的最高枚举值 |
|----------|----------------|----------------------|
| DS10-TTL | 4M | 4000000 |
| DS10-R485 | 500K | 460800 |
| DS10-R232 | 200K | 115200 |

> **设置说明**：硬件上限不是额外的可输入值。设置时仍需从上方枚举中选择，例如 DS10-R485 的 500K 上限内，最高可选枚举值是 460800。

### 5.2 SLE 发射功率

点击"功率档位"，可在 `0x00–0x07` 中选择。档位越高，信号覆盖能力通常越强，设备功耗也会相应增加。

> **设置建议**：先使用满足现场通信距离的较低档位。如果通信不稳定或距离较远，再逐步提高功率档位。

### 5.3 软调试模式

开启软调试后，在 RUN 模式下，可通过串口发送触发指令（例如 `+++`），使设备进入 AT 软调试模式。适合 MCU 与 DS10 对接调试。

进入流程：`保持空闲 ≥ 500 ms → 发送 +++（不可带回车或换行）→ 再次空闲 ≥ 500 ms → 进入 AT 配置模式`

> **退出调试**：发送 `AT+ENTM\r\n`，设备退出 AT 模式并恢复正常传输。

### 5.4 STATUS 引脚作用

> **输出特性**：STATUS 引脚为开漏输出，最大允许电流为 1 A。导通时将引脚拉到低电平；关闭时引脚呈高阻态，不能主动输出高电平。使用时需要由外部电路提供上拉或负载。

**01 · NETWORK 网络状态**：用于指示设备的 SLE 网络连接状态。

| SLE 状态 | STATUS 输出 |
|----------|-------------|
| 连接成功 | 低电平（导通） |
| 连接断开 | 高阻态（不导通） |

适用于检测 SLE 网络是否已经连接。

**02 · SWITCH 开关命令**：用于通过 SLE 远程控制外部开关设备。

| 过程 | 说明 |
|------|------|
| 配置命令 | 分别设置"开"和"关"的触发命令。 |
| 接收命令 | 设备通过 SLE 接收并匹配已配置的命令。 |
| 执行动作 | STATUS 引脚执行对应的导通或断开动作。 |

**完成标准**：串口设置正确；功率档位合适；没有开启不需要的软调试或 STATUS 功能。

## 06 保存、核对并投入使用

配置完成后，按照"保存 → 重新读取 → 按角色核对 → 切换 RUN"的顺序收尾。主机和从机都必须完成本章。

### 6.1 保存并重新读取

1. **保存配置**：点击页面底部"保存配置"，等待保存成功提示。
2. **重新读取**：再次点击"读取配置"，用设备内部已保存的值刷新页面。
3. **比对结果**：将重新读取的内容与刚才设置的内容逐项对照。

> **必须确认**：在页面上修改设置，并不代表设备已经保存。重新读取后，如果所有内容与预期一致，才能继续切换 RUN。

### 6.2 按设备角色核对

| 核对项 | 主机 | 从机 |
|--------|:----:|:----:|
| 主 / 从切换 | ✓ | ✓ |
| 主机配置 | ✓ | — |
| 通道管理 | ✓ | — |
| 硬件配置 | ✓ | ✓ |
| 重新读取一致 | ✓ | ✓ |

> ✓ 需要核对 · — 当前角色不显示

### 6.3 将硬件切换到 RUN 模式

1. **确认配置一致**：重新读取后，主机 / 从机选择和所有需要的参数均与预期一致。
2. **找到硬件开关**：在 DS10 模块上找到标有"RUN / DEBUG"的拨动开关。
3. **拨到 RUN**：将开关从 DEBUG 侧拨到 RUN 侧。此时配置流程完成，设备可以投入使用。

> **不要提前切换**：如果重新读取的结果不一致，请保持 DEBUG，修正并重新保存。

*（图 6-1：DS10 的 RUN / DEBUG 开关，配置检查通过后拨到 RUN）*

**完成标准**：已保存 · 已重新读取 · 配置完全一致 · 已切换 RUN

## 07 维护与常见问题

本章不属于每次都要执行的配置流程。只有需要升级固件或遇到问题时再查看。

### 7.1 正常工作灯态

| 指示灯 | 作用 |
|--------|------|
| 状态灯 | 双色灯，可显示红、绿、黄三种颜色，用于表示设备角色、连接状态和异常状态。 |
| DATA 灯 | 单色数据灯，用于表示数据收发、复位确认和 OTA 数据传输。 |

| 设备状态 | 状态灯表现 | 含义 |
|----------|------------|------|
| 主机 | 绿灯快速闪烁（约 2 次/秒） | 没有从机上线就绪。 |
| 主机 | 绿灯双闪（约每 0.8 秒一个周期） | 部分从机已上线，仍有已配置从机未上线。 |
| 主机 | 绿灯常亮 | 所有已配置从机均已上线就绪。 |
| 从机 | 黄灯慢闪（约 1 次/秒） | 正在等待连接主机。 |
| 从机 | 黄灯常亮 | 已连接主机，可以正常通信。 |
| DEBUG | 红灯慢闪（约 1 次/秒） | 等待手机或其他 BLE 配置终端连接。 |
| DEBUG | 红灯常亮 | BLE 配置终端已经连接。 |
| DEBUG | 红、绿快速交替闪烁 | 设备 SN 未配置或无效，需要完成初始化配置。 |
| DEBUG | 红灯常亮时短暂出现绿光 | 正在收发数据，属于正常现象；DATA 灯也可能闪烁。 |
| 设备启动 | 红、绿快速交替闪烁 | 设备正在启动和初始化。启动完成后会自动进入对应角色的灯态。 |

> **主机灯态**：主机状态灯反映的是所有已配置从机的整体上线情况，不只代表其中一台从机。
>
> **启动异常**：如果启动后长时间保持红、绿快速交替闪烁，请检查设备是否处于 DEBUG 模式，以及 SN 是否已经正确配置。

### 7.2 DATA 灯与特殊提示

**DATA 数据灯**

| DATA 灯表现 | 含义 |
|-------------|------|
| 熄灭 | 当前没有数据活动。 |
| 短促、快速或持续抖动式闪烁 | 正在进行普通数据收发；高频通信时灯不会保持常亮。 |
| 单闪 | 收到一帧完整的 IOB 数据。 |
| 连续双闪 | 正在发送 IOB 数据。 |

> **判断原则**：DATA 灯只表示数据活动。闪烁不代表故障，也不能单独说明连接已经建立；连接状态请以双色状态灯为准。

**版本、按键与 OTA 提示**

| 场景 | 灯光表现 | 含义或操作 |
|------|----------|------------|
| 本机固件版本偏低 | 正常绿灯或黄灯中，每 2 秒插入约 100 ms 红光 | 通信不会停止，建议升级本机固件。对端断开或版本条件消失后，红色提示停止。 |
| 按键不足 5 秒 | 所有灯熄灭 | 处于确认阶段；此时释放不会恢复出厂设置。 |
| 按键 5–10 秒 | 状态灯红色快闪，DATA 灯同步快闪 | 释放按键后恢复出厂设置。 |
| RUN 主机按键达到 10 秒 | 状态灯绿色快闪，DATA 灯同步快闪 | 释放按键后发起主机 OTA。 |
| OTA 等待 | 主机绿/红交替，从机黄/红交替 | 单色约保持 500 ms，DATA 灯熄灭。 |
| OTA 传输或应用 | 传输时约 100 ms 快速交替，应用时约 250 ms 交替 | 传输数据时 DATA 灯闪烁；校验或应用固件时 DATA 灯熄灭。 |
| OTA 失败 | 红灯连续三闪（约每 2 秒重复） | 重新发起升级，或重启设备后重试。 |

> **OTA 注意**：OTA 过程中不要断电。升级完成后，设备会退出 OTA 灯态或自动重启，并恢复正常指示。
>
> **显示优先级**：按键确认 → OTA 失败 → OTA 等待 / 传输 / 校验 → 版本偏低提示 → 角色与连接状态 → DATA 数据活动。特殊状态显示时，正常连接灯态可能暂时不显示。

### 7.3 固件在线升级

设备连接并读取后，如果服务器上有新固件，"软件版本"旁会显示"发现新版本"。

1. **打开升级弹窗**：点击"发现新版本"或设备卡片中的"升级"。
2. **查看版本说明**：选择要升级的版本，并阅读更新内容。
3. **等待升级完成**：手机靠近设备，不要退出小程序。升级完成后，设备会自动重启。
4. **重新连接检查**：重新连接并读取，确认软件版本和主要设置都正确。

*（图 7-1：版本、升级与连接控制）*

**通过主机统一升级从机**

> **升级策略**：主从设备完成配网后，如需升级整套设备，只需要先通过小程序升级主机。主机升级完成后，可在 RUN 模式下自动为已经组网的从机进行 OTA 升级。

1. **先升级主机**：按照上方流程，通过小程序把主机升级到目标固件版本。
2. **进入 RUN 并完成组网**：将主机和所有从机的硬件开关拨到 RUN，等待主机与从机连接完成。
3. **长按主机 RESET**：长按主机的 RESET 按键约 10 秒；看到绿色状态灯与蓝色 DATA 灯快速闪烁后松开按键。
4. **自动升级全部从机**：主机进入 OTA 状态，并自动向所有已经上线的从机传输和升级固件。

> **升级期间**：确认所有需要升级的从机都已经上线。OTA 完成前不要断电，也不要让主机或从机退出 RUN 模式。

### 常见问题

先根据看到的问题查找原因。重新连接设备后，请先读取配置，再继续修改。

**Q1　保存时提示"写入失败"或没有响应**

1. 检查顶部状态是否已经断开。
2. 重新建立连接，并先执行一次"读取配置"。
3. 重新修改参数后点击"保存配置"。

**Q2　扫描附近设备一直转圈，找不到从机**

1. 确认从机正常上电且广播已开启。
2. 确认主机已经通过蓝牙连接。
3. 检查从机是否已经绑定；系统会过滤当前主机中已绑定的 SN。
4. Android 手机检查定位服务是否开启。

**Q3　从机仍然收不到主机数据**

1. 确认通道已使能，绑定 SN 与机身标签一致。
2. 使用 Modbus 模式时，检查数据中的站号是否已经添加到对应通道。
3. 核对两端串口的波特率、数据位、校验位和停止位。
4. 确认修改后已经保存，并重新读取检查。

**Q4　切换为从机后，"通道管理"消失**

这是正常现象。从机不负责管理其他设备，所以只显示"硬件配置"。如果需要管理通道，请把设备切回主机（Master）。

**Q5　发送 +++ 无法进入软调试**

请检查发送顺序：发送 `+++` 前后，串口都要保持至少 500 ms 不发送数据；`+++` 后面不能带回车或换行。使用串口调试助手时，请关闭"发送新行"或"自动添加回车换行"。

**Q6　上电后灯不亮或设备启动失败**

电源供电能力不足时，设备可能无法正常启动。启动失败后，设备会等待约 15 秒，然后自动尝试重启。如果出现上电后指示灯不亮、设备无法正常进入工作状态，或间隔一段时间重复启动，请优先检查电源的输出能力、供电电压和接线是否可靠。

> **操作原则**：每次换设备，都重新核对 SN、建立连接并先读取，再继续修改。
