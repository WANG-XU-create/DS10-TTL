1 使用前说明
 1.1 使用 AT 前的先决条件
  必须先在 小程序或上位机 的 硬件配置 中，将 “AT 指令配置通道” 设为 启动，并保存或下发配置。未启
  动该通道时，设备无法进入或使用 AT 会话。


1. 先将设备开关调整至 DEBUG 模式。
2. 通过小程序（蓝牙）或上位机（串口）连接设备。
3. 在 硬件配置 中启动 “AT 指令配置通道”，并下发配置。
4. 将设备开关调整至 RUN 模式；随后通过串口发送触发指令（例如 +++），即可进入 AT 模式。

2 AT 使用总览
首次配置或现场调试时，建议按以下顺序执行。每一步都列出了对应的 AT 命令，可在进入命令参考前先了解
完整操作路径。


 2.1 两种 AT 平面
进入 AT 会话后，设备根据是否已创建配置草稿，工作在运行态 AT 或配置态 AT。两个平面的用途和数据影响
不同：

 平面               进入方式                   适用操作

 运行态 AT           进入 AT 会话后的默认           查询设备与链路状态，以及不写入 Flash 的即时控制。不会
                  平面                     修改配置草稿。

 配置态 AT           在运行态执行                 修改角色、无线、业务、通道和硬件配置。命令操作 RAM 草
                  AT+CFG_NEW 后进入         稿，保存并重启后才会生效。



  平面切换与草稿处理

   进入运行态          +++ → AT → 运行态 AT
   进入配置态          AT+CFG_NEW → 配置态 AT
   结束配置           AT+CFG_SAVE（保存并重启） / AT+CFG_DISCARD（放弃草稿）



配置态命令默认操作 RAM 草稿，不会立即改变正在运行的配置。除草稿创建和状态查询等例外命令外，配置
命令要求草稿已经存在；否则会返回 +DS10ERR:2,CFG_NOT_LOADED。


  通过在线配置工具生成 AT 命令

  如果不希望手工组合参数，可先在 DS10 在线配置工具中完成配置，再点击页面中的 “AT 翻译器”。系
  统会根据当前界面配置生成对应的 AT 命令，用户可按生成顺序通过串口发送。

  https://app.bearpi.cn/pwm/ds10/?fw=1.0.0

  网页只负责生成命令，不会自动写入设备；设备仍须先开启“AT 指令配置通道”并进入 AT 模式。




                     AT 配置翻译器会按执行顺序列出命令，可逐条复制，也可一次复制全部命令。

 2.2 进入会话与基础配置
         进入 AT 会话
   01

         从 RUN 数据透传进入调试会话，并确认串口连接正常。

         +++      ·   AT

         确认设备能力
   02

         先读取型号、版本和能力列表，避免调用当前固件未支持的功能。

         AT+DEVINFO?       ·   AT+CAP?

         创建配置草稿
   03

         创建默认业务配置草稿，同时加载设备当前硬件配置，进入配置 AT。

         AT+CFG_NEW

         加载现有配置（可选）
   04

         若仅修改当前已生效配置的一部分，在草稿创建成功后加载现有配置。

         AT+CFG_LOAD

         设置角色与无线参数
   05

         确定主从角色，再选择 SLE 无线预设；有特殊需求时使用专家参数。

         AT+CFG_ROLE=<role>       ·   AT+CFG_SLE=<frameType>,<tier>   ·   AT+CFG_SLEC=...

         设置业务模式
   06

         选择广播、Modbus 或规则路由；按需继续设置广播和 NTP 规则。

         AT+CFG_WORK=<mode>       ·   AT+CFG_BCAST=<type>   ·   AT+CFG_NTP=...

 2.3 通道、硬件与保存生效
         配置从机通道
   07

         按所选业务模式启用通道，并设置设备 SN、Modbus ID 或路由规则。

         AT+CFG_CH=<channel>,...            ·       AT+CFG_GETCH=<channel>

         配置本机硬件
   08

         按现场接线设置 RUN UART、SLE 发射功率及 STATUS 引脚用途。

         AT+CFG_UART=...           ·    AT+CFG_POWER=<level>       ·   AT+CFG_STATUS=...

         检查草稿
   09

         保存前检查草稿是否存在、是否已修改，并查看角色、业务与硬件摘要。

         AT+CFG_STATE?         ·       AT+CFG_SHOW?

         保存并重启生效
   10

         保存前由固件校验全部组合规则；收到 OK 后设备会重启。

         AT+CFG_SAVE

         重新进入并运行诊断
   11

         重启完成后再次进入 AT，确认运行状态与 SLE 链路是否符合预期。

         AT+STATE?       ·     AT+LINK?         ·    AT+GETLINK=<channel>

         结束 AT 会话
   12

         无需继续操作时退出 AT，恢复 RUN 数据透传。草稿未保存时需先保存或丢弃。

         AT+ENTM     ·       AT+CFG_DISCARD


 注意： 草稿已修改时不能直接执行 AT+ENTM；请先执行 AT+CFG_SAVE 保存，或执行 AT+CFG_DISCARD 放弃修
 改。

  AT+CFG_CH                      管理从机逻辑通道、设备绑定及业务路由规则。

  先理解：channel 是什么

  channel 是主机配置中的从机逻辑槽位，不是 UART 端口、SLE 频道或 Modbus 地址。每个启用的 channel 通过 SN
  绑定一台目标从机；主机保存后重启，才会在 RUN 中按该绑定扫描、建链和转发数据。



工作模式决定每个通道如何接收数据

 全局工作模式       通道配置                业务含义
 广播           属性 0 + 1            启用并绑定需要参与通信的从机；可靠、IOB 或智能混合由全局
 CFG_WORK=0                       CFG_BCAST 系列命令决定。

 Modbus       属性 0 + 1 + 2        主机读取请求中的从站地址，再将请求路由到配置了该地址的通
 CFG_WORK=1                       道。
 自定义路由        属性 0 + 1 + 3；属性     主机按自定义内容匹配请求；从机回复可原样输出，也可增加通道
 CFG_WORK=2   4 可选                识别信息。


命令族总览

 属性               用途                     说明
 查询               通道列表                   AT+CFG_CH? 查看全部通道的启用和绑定摘要
 查询               通道详情                   AT+CFG_GETCH=​<channel> 查看单个通道的完整配置
 0                通道启停                   决定逻辑通道是否参与连接和业务转发
 1                绑定从机                   通过 SN 确定该通道对应的目标从机
 2                Modbus 地址路由            按从站地址或地址范围路由请求
 3                自定义请求匹配                按数据内容决定请求应发送到哪个通道
 4                从机回复封装                 为返回数据添加文本或二进制识别头

 统一命令格式

 AT+CFG_CH=<channel>,<property>,<arguments...>

 默认支持通道 1..15，实际上限以 AT+DEVINFO? 返回值的最后一个字段 maxSlaves 为准。

 AT+CFG_CH 只修改 RAM 草稿，不会立即改变连接或数据流。修改现有配置通常依次执行 AT+CFG_NEW、
 AT+CFG_LOAD；修改完成后执行 AT+CFG_SAVE，保存成功后设备重启。



 推荐配置顺序

 01   执行 CFG_NEW 创建草稿；修改已有配置时再执行 CFG_LOAD。
 02   确认 CFG_ROLE=0，再通过 CFG_WORK 选择广播、Modbus 或自定义路由。
 03   先用属性 0 启用通道，再用属性 1 设置设备 SN。
 04   广播模式无需额外通道规则；Modbus 配置属性 2；自定义路由配置属性 3，按需配置属性 4。
 05   执行 CFG_GETCH 检查，确认后执行 CFG_SAVE。

 切换 CFG_WORK 时，固件会清除与新工作模式不兼容的旧通道规则，并通过 RESET: 返回被清理的属性数量。
